## Seed/reset

`scripts/seed/seed.ts` resets through A0's empty `SandboxResetRequestSchema`,
then creates the four neutral recipients with deterministic `Idempotency-Key`s.
It never writes Postgres. Endpoint creation is deliberately stopped: A0 has no
`POST /v1/endpoints` request schema, so the runner blocks instead of sending
invented fields.

Executed against the launcher API at `http://127.0.0.1:8899`:

```bash
FP_API_URL=http://127.0.0.1:8899 FP_API_KEY=demo-not-a-real-key \
FP_SETTLEMENT=mock node scripts/seed/seed.ts
# exit 2, result BLOCKED
# blocked POST /v1/sandbox/reset is not mounted [owner: Csaba (CC3b)]
# evidence scripts/demo/evidence/seed-mock-2026-10-23T13-10-55-647Z.json
```

The generated evidence record contains only the commit, command, steps and
blocker; the placeholder key is redacted. `seed reset` follows the same path.

Unit checks with a loopback stub prove:

- reset sends exactly `{}` with `Idempotency-Key: seed:reset`;
- a 404 reset blocks before any recipient is created;
- recipients use the fixture name/kind/country and `seed:recipient:<ref>`;
- a missing endpoint route or missing A0 schema blocks **before**
  `POST /v1/endpoints` is called.

## Offline launcher

`scripts/demo/offline.ts` starts only the existing development commands:

```bash
FP_API_PORT=8899 FP_WEB_PORT=5299 \
  sandbox-exec -f /tmp/fp-offline.sb node scripts/demo/offline.ts --no-seed
```

The sandbox profile denies all network except loopback and local Unix sockets
(`sandbox-exec` is a macOS local facility, not an admin command). External
`curl http://example.com` inside the same profile fails; loopback works. This is
the offline condition the demo must survive.
