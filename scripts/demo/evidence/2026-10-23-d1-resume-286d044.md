### Reset replay defect found and fixed

With the original fixed `Idempotency-Key: seed:reset`, the API's idempotency
middleware replayed the first cached 200 and **did not execute the wipe**. A
second seed therefore reused the first recipients (same ids, same `createdAt`),
and reset-only could not clear the DB. Removing the header from`runSeed.reset`
fixes it; a second seed now resets and creates fresh ids. Commit **`be9a654`**.
The two seed-runner tests that asserted the old key and "no schema" message were
updated to assert **no** reset key and the mounted CCR-16 route gap; all four
pass at `68a933b`. This is lane-D code only; no API change.
